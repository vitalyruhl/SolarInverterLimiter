# PV-follow mode implementation plan

Owner-approved scope: append `pv_follow` (enum value 3) with HA label `PV-Folger`.
Keep legacy values 0..2 and all existing settings unchanged. Version: 5.6.0.

1. Add failing portable and actual-output tests for fresh PV bounded by corrected
   household demand/MAX, night/invalid/stale PV, BMS uncertainty, low-SOC PV use,
   real fault/OFF gates, four-mode command/profile compatibility, and full-charge
   latch release across mode changes. Implement only those contracts.
2. Extend parser, CM presentation, confirmed MQTT state and additive HA select.
   Reuse staged persistence and the single corrected manual-output boundary.
   No battery discharge budget, MOS write or recovery-policy change.
3. Investigate the existing automatic `bms_unverified` observation from local
   captured evidence and actual source contracts; distinguish confirmed faults
   from warm-up hypotheses. Do not weaken source qualification without evidence.
4. Update operating documentation and runtime/build version mirrors; execute
   relevant host regressions and USB/OTA builds without uploading. Hand off for
   fresh review and parent-owned TestESP/production acceptance. No commit/push.

PV demand is `min(fresh DC charger W * 0.90, clamp(H + correction, 0, MAX))`.
Reserve/discharge permission alone does not reject this solar-only request;
genuine discharge protection and charger faults still stop it. Missing BMS
never means physical battery absence and is explicitly reported in the reason.
